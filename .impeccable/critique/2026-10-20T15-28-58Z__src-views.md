## What's Working

- The transcript workspace retains the collection and manages focus when switching between list and reader (`src/ui/TranscriptWorkspace.tsx:40-74`).
- Subscription refresh lets users choose when refreshed videos appear and explains when previous videos were kept (`src/views/SubscriptionView.tsx:908-918`).
- Liked-video filters expose removable active-filter chips, announce result counts, and offer a clear-all path (`src/views/LikedVideoView.tsx:699-724`, `804-825`).

## Priority Issues

1. **[P2] Summary reading leaves collection controls in view while hiding the collection.** Search, sort, source filters, and result count sit outside the list/detail workspace (`src/views/AISummariesView.tsx:186-214`). At narrow widths the list is hidden, but these controls remain; the selected summary is resolved from all saved summaries, not the filtered list (`src/views/AISummariesView.tsx:114-118`). Move controls into the list region in split view and hide them with the list in narrow view. Keep "All summaries" as the return path. Suggested command: `$impeccable adapt`.

2. **[P2] Empty playlist copy points away from an existing in-pane action.** The empty state says "Create playlists on YouTube to see them here" (`src/views/UserPlaylistsView.tsx:400-410`), but the header has an "Add playlist by ID or URL" action (`src/views/UserPlaylistsView.tsx:320-328`). Add a visible empty-state route to that existing form, and give the AI-summary empty state a concrete route to video actions that generate summaries (`src/views/AISummariesView.tsx:217-222`). Suggested command: `$impeccable onboard`.

3. **[P2] Subscription loading and error changes lack explicit announcement semantics.** Initial loading and error states are plain containers (`src/views/SubscriptionView.tsx:842-875`); partial-failure and refresh-error notices also lack status/alert roles (`src/views/SubscriptionView.tsx:914-968`). Neighboring playlist states use `role="status"` and `role="alert"` (`src/views/UserPlaylistsView.tsx:255`, `280`). Add scoped announcements and label the progress element. Suggested command: `$impeccable harden`.

4. **[P2] Shared pane titles have no heading semantics.** `ViewHeader` renders title text in generic `div`s (`src/ui/ViewHeader.tsx:18-23`). Use the correct heading level for the pane context, reset default margins, and keep actions outside the heading. Suggested command: `$impeccable harden`.

## Cognitive Load

Collapsed filters and removable active chips keep the default browsing view manageable. Expanding liked-video filters reveals multiple controls across named groups, so density warrants a rendered narrow-pane check; source review alone cannot establish that it is overwhelming. The clearest avoidable mental demand is the summary reader retaining controls for a hidden collection.

## Emotional Journey

Subscription loading gives users a clear scope and direct action. Browsing builds confidence through counts and active filters. The strongest moment is moving from a video collection into transcript/summary reading and saving a note. Empty summaries provide no route into that moment, and the playlist empty-state copy suggests leaving Geulo. Partial-failure messaging protects trust, but it should also reach screen readers.

## Persona Red Flags

- **Jordan, first-timer:** The empty playlist message suggests creating a playlist on YouTube is the only path, while the supported URL-add action is a labeled icon in the header. The empty summaries view does not explain how to create the first one.
- **Sam, keyboard/screen-reader user:** Pane titles are absent from heading navigation. Subscription loading and error transitions lack explicit announcement roles, despite stronger focus handling in the transcript workspace.
- **Alex, frequent researcher:** Searching or filtering while a summary is open changes the collection count while the detail remains selected, making it unclear which content the controls affect.

## Minor Observations

- The shared header uses a clipped title and nonshrinking actions (`styles.css:608-652`). Long playlist titles may compete for space in narrow panes; this needs visual verification before treating it as a defect.
- The AI-summary list shows source type, but the detail hides source/model metadata (`src/views/AISummariesView.tsx:239-244`, `293-308`). Consider a compact provenance disclosure.
- The summary pane uses a native sort select while other panes use menus. This is a small consistency difference, not a reason by itself to force uniformity.

## Questions to Consider

- In a narrow pane with a summary open, should the user be reading one document or browsing the collection?
- Can every empty pane show one direct route to its first useful result?
- Which provenance details help users judge a generated summary before saving it into their notes?
